## 三、Part 2：端侧设备信息对照

### 3.1 逐项对照

| 需求 | 当前实现 | 状态 | 说明 |
|------|---------|------|------|
| ① GPU/NPU 使用率 | `gpu_usage_percent`（GPU HW active residency）+ `npu_usage_percent`（ANE duty cycle），2s 粒度落盘 metrics.jsonl | ✅ 整体级满足 | Apple 不暴露"各核心"级 GPU/ANE 占用；GPU active residency 附带频率分布直方图（P1~P13），比单一百分比信息更多 |
| ② CPU 使用率 | `top -l`：system-wide user/sys/idle（整体） | ⚠️ 部分：缺 per-core/cluster 粒度 | ✅ **可补**：powermetrics 已在采 `cpu_power`，其输出含 **P-Cluster / E-Cluster 的 HW active residency + frequency**（大小核簇粒度），monitor_machine.py 目前不解析——加 2 条正则即可落盘 |
| ③ 内存（含显存） | `vm_stat`：free/active/inactive/wired/purgeable/compressor/available/total + swap | ✅ 满足（除显存） | "已用/空闲/缓存/可用"全有。**显存不可直接测**：Apple 统一内存架构无独立 VRAM 计数器，GPU 显存即 wired 内存的一部分，无法单独读数——只能用 wired 总量 + GPU residency 间接说明，报告中标注架构限制 |
| ④ 算力 | 理论峰值 `--theoretical-tflops`（静态基线）+ 实测推导 `effective_tflops`（prefill/decode 分相，`tokens/s × FLOPs/token`），量化单位 `--quantization` 入 manifest | ✅ 满足（推导口径） | 推导值已在 manifest/图表标注 `measurement: derived_*`，不是硬件计数器——这是 macOS 无用户态算力计数器下的正确做法；MoE 需显式给激活参数口径（脚本已预留分阶段参数） |
| ⑤ GPU/NPU 带宽 | 理论值 `--official-bandwidth-gb-s` 参数；实测推导 `effective_bandwidth_gb_s`（分相） | ⚠️ 理论可配、实测仅推导 | **实时带宽硬件计数器不可得**：macOS 不向用户态暴露 DRAM 总线带宽计数器（powermetrics 无此 sampler）。推导值 `tokens/s × bytes/token` 已实现且口径标注清楚。需求文档的"官方理论值 120GB/s"作为参数传入即可 |

### 3.2 Part 2 缺口汇总

| 缺口 | 可否补 | 方案 |
|------|--------|------|
| CPU per-cluster（P核簇/E核簇）使用率与频率 | ✅ 可补 | monitor_machine.py 加 `P\d-Cluster HW active residency/frequency`、`E-Cluster` 正则（powermetrics cpu_power 采样器已在运行，零额外开销） |
| 显存单独读数 | ❌ 不可补 | 统一内存架构无 VRAM 计数器；报告中用 wired + GPU residency 说明，标注架构限制 |
| 实时内存带宽实测 | ❌ 不可补 | macOS 无用户态带宽计数器；保留 effective 推导口径，理论值作静态基线传入 |
| CPU 单核粒度 | ❌ 不可补 | 用户态最高只能到 P/E cluster 级；单核使用率 macOS 无公开 API |

## 四、补齐改动清单（建议优先级）

### P2：服务端能力验证 — ✅ 已完成（2026-11-26）

实测 Splash（jiuwen 127.0.0.1:18080）确认：`usage.prompt_tokens_details.cached_tokens` 与 `usage.completion_tokens_details.reasoning_tokens` 均返回，`message.reasoning_content` 独立字段存在。三个需求字段全部可补。

### P3：monitor 增加 CPU cluster 解析（monitor_machine.py）— ✅ 已实现（2026-11-26，真实 powermetrics 数据验证通过）

- 新增正则解析 `P\d-Cluster / E-Cluster HW active residency/frequency`（cpu_power 采样器已在运行，零额外开销）

- 方案 B：bench 进程内用 psutil 自采进程 RSS（精度高，但只有 bench 进程视角，含不了服务端）
- 建议 A：与文档 per_request_machine 字段近似对齐，标注 `sampling_window: 2s`
